# RC522 与 RFID 卡入门

本文介绍本项目中的 RC522 读卡模块、配套测试卡、常见应用、命令行操作和固件接口。项目目标是用 STM32F103C8T6 学习 ISO14443A 近场通信；它是实验平台，不是通用门禁复制器。

## RFID 是什么

RFID（射频识别）由读写器和标签组成。读写器产生射频场，近距离给无源卡片供能并与之交换数据；卡片靠近天线时才可能响应。RC522 工作在 **13.56 MHz**，本项目使用 ISO14443A 通信。常见的另一类门禁扣工作在 **125 kHz**，RC522 无法检测它。13.56 MHz 也有不同协议，例如 ISO14443B；频率相同不代表 RC522 一定兼容。

卡片的 UID 是识别标签时取得的编号，不等于卡内所有数据，也不必然是安全凭据。MIFARE Classic 还会对扇区数据访问进行密钥认证。只知道或读到 UID，不能据此推断卡片容量、权限或能否写入。

## 常见应用与能力边界

RFID 常用于经授权的门禁、考勤、图书借阅、物品盘点、设备配对和教学实验。实际系统通常还需要后台记录、权限判断和安全认证；读卡器读出 UID 并不等于完成了安全门禁验证。

RC522 适合学习近场通信、卡片寻卡、防冲突、UID 读取和部分 MIFARE Classic 操作。它不能读取 125 kHz 卡，也不能靠固件升级支持所有 NFC/RFID 协议。天线线圈、卡片天线和摆放方向影响感应距离；本项目把接收增益设为较高值并重试寻卡，但软件不会因此增加天线发射功率。普通小型 RC522 模块的可靠读取距离通常是贴近天线的几厘米量级，具体取决于模块和卡片。

## 本项目硬件与连接

先断开开发板电源，再按表连接。RC522 的排针标注因模块而异；表中的 `SDA` 在 SPI 模式下实际用作片选 `SS/NSS`。

### RC522 与 STM32F103C8T6

| RC522 模块引脚 | STM32F103C8T6 Blue Pill | 用途 |
|---|---|---|
| `SDA` / `SS` | `PA4` | SPI 片选 |
| `SCK` | `PA5` | SPI 时钟 |
| `MISO` | `PA6` | RC522 到 STM32 的数据 |
| `MOSI` | `PA7` | STM32 到 RC522 的数据 |
| `RST` / `NRST` | `PB0` | 模块复位，由固件控制 |
| `3.3V` | `3V3` | 电源；不要接 5 V |
| `GND` | `GND` | 地线，共地 |
| `IRQ` | 不连接 | 本固件未使用中断输出 |

```text
STM32F103C8T6                 RC522
PA4  ----------------------> SDA / SS
PA5  ----------------------> SCK
PA6  <---------------------- MISO
PA7  ----------------------> MOSI
PB0  ----------------------> RST
3V3  ----------------------> 3.3V
GND  ----------------------> GND
                               IRQ (不接)
```

### 三针无源蜂鸣器模块

蜂鸣器接到 STM32，不接 RC522。模块上的 `S / + / −` 通常分别表示信号输入、电源正极和地：

| 蜂鸣器模块引脚 | STM32F103C8T6 Blue Pill | 说明 |
|---|---|---|
| `S` | `PB1` | PWM 信号（TIM3_CH4，约 2 kHz） |
| `+` | 模块标注的额定电压 | 按模块规格供电；不要仅凭引脚标签猜电压 |
| `−` | `GND` | 与 STM32 共地 |

确认模块的 `S` 输入能识别 3.3 V 高电平。蜂鸣器和 RC522 都要与 STM32 共地。裸两针蜂鸣器不是这种三针模块；若电流超出 GPIO 能力，应加三极管驱动，不能直接照搬 `S/+/-` 接法。

### USB 与 ST-Link

- Blue Pill 的 micro-USB 口接电脑数据线，用作 USB CDC 命令串口。
- ST-Link 用于烧录/调试，连接板上专用 `SWDIO`、`SWCLK` 和 `GND` 引脚；需要时再接 `NRST`。这些是 ST-Link 调试连接，不是 RC522 的 SPI 接线。SWDIO/SWCLK 在芯片上分别对应 PA13/PA14，开发板通常已经把它们引到标注的专用排针。
- 首次上电前检查 RC522 供电确为 3.3 V、各模块地线相通，且 SPI 信号没有接反。

## 从上电到读卡

1. 用数据线连接 Blue Pill 的 USB 口；终端打开新出现的串口，通常选 `115200, 8N1`。USB CDC 实际不依赖串口波特率，但终端程序常要求填写它。
2. 复位开发板，看到 `RC522 ready` 后输入 `help`。`status` 应显示 RC522 版本寄存器（常见模块通常是 `0x91` 或 `0x92`；克隆芯片也可能报告其他值）。
3. 将卡片平贴在 RC522 天线中央，输入 `scan`。成功时显示 UID 字节、UID 长度、SAK 和类型提示。SAK 是协议选择阶段返回的类型信息，不能单独证明卡片容量或真实性。
4. 对 MIFARE Classic 测试卡，先读普通数据块；确认卡片内容可丢弃后，再测试写、复制、擦除。写入和擦除会立即更改卡片。

```text
scan
read 4
write 4 112233445566778899AABBCCDDEEFF00
read 4
copy 4 5
read 5
erase 4 YES
read 4
```

块号使用十进制。上例中块 4 和 5 位于同一扇区。复制目前只支持同一张卡、同一扇区内的普通数据块。擦除是把 16 个数据字节写成 `00`，不是把卡片恢复出厂或擦掉 UID。

## 命令与固件接口

| 命令 | 作用 |
|---|---|
| `help` | 显示命令菜单 |
| `status` | 读取 RC522 `VersionReg`，用于快速检查 SPI 通信 |
| `scan` | 唤醒/寻卡、完成 UID 级联选择，显示 4/7/10 字节 UID 和 SAK |
| `read <block>` | 用默认 Key A 认证并读取一个数据块 |
| `write <block> <32 hex>` | 将 16 字节十六进制数据写入数据块 |
| `erase <block> YES` | 将数据块写为 16 个零字节；`YES` 是显式确认 |
| `copy <src> <dst>` | 读源数据块，再写入同卡同扇区内的目标数据块 |

当前数据操作仅面向识别为 MIFARE Classic 1K/4K、且扇区使用默认 Key A `FF FF FF FF FF FF` 的卡。固件拒绝 block 0（厂商/UID 数据）以及扇区 trailer（密钥和访问位）。它不尝试破解密钥、不写 UID、不改扇区密钥、不复制整张卡，也不读写其他卡型。

命令行是本固件提供给用户的操作接口；C 函数目前是 `src/main.c` 内部的 `static` 实现，不是可供外部程序链接的稳定库 API。主要调用层次如下：

- `shell_poll()` 接收 USB CDC 字节并解析命令；`command_card()` 执行卡片命令；`print_line()` 回传终端输出。
- `rc_read()` / `rc_write()` 读写 RC522 寄存器；`rc_transceive()` 发送和接收 ISO14443A 帧；`rc_crc_a()` 计算 CRC_A。
- `read_uid()` 处理 REQA/WUPA、级联防冲突和 SELECT；`authenticate()` 执行 MIFARE Classic 扇区认证。
- `mifare_read_block()` / `mifare_write_block()` 实现 Classic 数据块读写；上层命令负责权限范围、参数校验和状态提示。

这种分层方便学习：先用 `status` 验证 SPI，再观察 `scan` 的寻卡过程，最后理解认证和数据块读写。若把它扩展成可复用库，可将 RC522 驱动、卡片协议和 USB 命令行拆成独立模块，并通过公开头文件定义稳定接口。

## 安全和故障排查

- 只在自己拥有或获准测试的卡片上操作；先用空白测试卡，并在写入前保存可丢弃数据。不要尝试复制他人的门禁或支付凭证。
- Classic 默认密钥只适合演示。MIFARE Classic 的旧式加密不适合新设计的高安全门禁；新系统应选用具有现代安全认证的卡片和读写器，并由后台校验权限。
- `No ATQA response` 表示寻卡请求没有收到 ISO14443A 响应。可先移开其他卡、贴近天线中心、翻转方向，并确认白卡仍能扫描；若只有某枚卡无响应，可能是频率/协议不兼容、天线耦合差或卡片损坏。仅凭无响应无法断定具体频率。
- 能 `scan` 不代表能读数据。若 `read` 认证失败，卡片可能不是 Classic、扇区 Key A 不是默认值，或卡片/访问位不允许读取。
- 写入失败时检查卡片是否仍贴近天线、目标块是否为数据块、是否使用默认密钥，以及目标是否与源块处在同一扇区（仅适用于 `copy`）。
